# Deploy to Render and Vercel

## 1. Deploy the API on Render

Create a new **Blueprint** from this repository. Render reads `render.yaml` and
deploys the `backend` directory as the `ecommerce-api` web service.

Set these Render environment variables before deploying:

- `MONGO_URI`: MongoDB Atlas connection string.
- `ADMIN_EMAIL` and `ADMIN_PASSWORD`: administrator credentials.
- `CORS_ACCESS`: exact Vercel production origin, for example
  `https://your-shop.vercel.app`. Use commas for additional approved origins.
- `SERVER_URL`: the public Render API URL, for example
  `https://ecommerce-api.onrender.com`.
- `STORAGE_PROVIDER`: set to `cloudinary` for Cloudinary, or `local` for the
  server filesystem.
- When using Cloudinary: `CLOUDINARY_CLOUD_NAME`, `CLOUDINARY_API_KEY`, and
  `CLOUDINARY_API_SECRET`.

`JWT_SECRET` is generated by the Blueprint. Do not replace it on later deploys,
or existing sign-in sessions will be invalidated. Confirm that
`https://your-render-service.onrender.com/health` returns `{"status":"ok"}`.

## 2. Deploy the frontend on Vercel

Import the same repository as a Vercel project and set its **Root Directory**
to `frontend`. Vercel detects Vite and uses `frontend/vercel.json` so React
Router deep links work after a refresh.

Add this Vercel environment variable for Production (and Preview only if that
preview URL is also added to `CORS_ACCESS` on Render):

```text
VITE_BASE_URL=https://your-render-service.onrender.com
```

Deploy Vercel first if you need its final URL, then set `CORS_ACCESS` on Render
and redeploy the API. Do not include a trailing slash in either URL.

## Uploaded files

Set `STORAGE_PROVIDER=cloudinary` on Render. All current product, vendor,
category, collection, and banner uploads are then stored in Cloudinary. Set
`STORAGE_PROVIDER=local` only when the server has persistent storage:
`backend/uploads` is ephemeral on standard Render instances, so local files
can disappear on redeploy or restart.
